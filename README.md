# 我把校招这摊事拆给了四个对话

这套 skill 是我被每个公司都要重填简历折磨到发疯的时候做出来的。求职投简历真的太让人崩溃了！

投简历最耗时间的地方不在“写一份简历”。一份岗位要先看清楚招聘方是谁，岗位到底在哪个城市，信息来自哪里。投完以后还要记住自己投过什么，链接在哪，进度到哪。等面试通知来了，官网要求、面试题和自己的项目材料又各放在不同地方，临时翻起来真的很乱。

于是我把这摊事扔给了Codex，拆成四个对话，再加一个总控 skill，专门负责把它们安排好。

这就是这个仓库。它们共用同一个 Codex 项目文件夹，读取同一批个人资料，各自保留自己的聊天上下文。

## 先准备一个项目文件夹

先把自己的简历和相关信息文档放到一个文件夹里，再用这个文件夹新建 Codex 项目。后面四个对话都从这个项目取材料，简历更新以后也只需要维护这一份。

我会把这些东西放进去。

- 当前使用的简历
- 项目说明，以及能支撑项目经历的材料
- 证书和求职时会用到的其他文件
- 目标岗位、城市偏好和不能接受的条件
- 收集过的岗位信息和投递记录

文件名尽量能看出版本和用途，例如 `resume-current.pdf`、`project-notes.md`、`target-roles.md`。身份证号、账号密码和不准备交给模型的隐私材料不要放进项目。这个公开仓库里也没有个人简历和投递表，别人下载以后可以换成自己的资料。

## 我会让四个对话接力做什么

### 1. 校招助手

这一段交给 `resume-application-tracker`。

我投一个岗位时，希望它拿岗位要求逐条对照简历，告诉我哪些经历能接上，哪些地方缺事实，哪些说法听着像在给自己加戏。它可以帮我做简历版本、准备网申字段，把页面填到提交前。投递完成以后，还要按原来的 Excel 结构回填记录。

我比较在意最后这一步。投递记录不能只剩下公司名和一个日期，过几天回头看时，我还得知道投的是哪个岗位、从哪里投的、当前进展怎样。原表的格式、字段和已有记录也要保住，不能每次归档都重新发明一张表。

我会这样开始一轮工作。

```text
使用 $resume-application-tracker。读取当前项目里的最新版简历和相关材料，结合我提供的岗位要求，先找出匹配点、缺口和需要我补充的事实。可以准备简历、网申草稿和投递记录，但不要编造经历，也不要替我提交申请。
```

### 2. 校招晨报

这一段交给 `campus-job-research`。

我手里的岗位链接往往已经够多了。校招群、在线文档、小红书和 BOSS 都能发现线索，麻烦在于里面混着重复岗位、过期信息和只在平台上出现的转述。晨报要做的事情，是先从这些地方捞出值得看的线索，再回到招聘官网确认岗位还在不在、要求有没有变、能不能找到直投入口。

我会把自己的背景、工作意向、城市限制和已经投过的岗位放进项目。比如一个岗位看起来很合适，官网页面却已经关闭，或者招聘平台有岗位卡片，官网没有对应职位，这些情况都应该写出来。岗位详情链接和直投入口也要分开，找得到岗位不代表找得到提交按钮。

每天的结果可以按“今日优先投递”“可考虑”和“暂不建议”整理。这样打开晨报以后，我先看少量值得花时间的岗位，不用把收藏夹经营成第二个招聘网站。

我的起手式大概是这样。

```text
使用 $campus-job-research。根据当前项目里的背景、求职意向、城市限制和投递记录，结合我指定的信息源寻找岗位。信息源只作为线索，请优先回到官方招聘页面核验，把岗位详情链接、直投入口、截止时间和待确认内容分开写，并按今日优先投递、可考虑、暂不建议整理。
```

想让它每天自动跑，再补充发送时间、信息源和输出频率。定时任务解决的是按时去看，岗位值不值得投还要经过判断。

### 3. 校招老油条

这一段交给 `career-old-hand`。

晨报整理出一批岗位以后，我会先自己筛一遍。留下来的岗位通常都带着一点“看起来不错，但我总觉得哪里不对”的感觉，这时候再让它从职场经验和招聘风险的角度看一遍。

它要帮我问清楚几件事。这个岗位和候选人的背景接不接得上，工作内容能不能形成下一步成长，招聘链条是不是清楚，薪资福利、地点、出差和加班有没有模糊的地方，背调和劳动关系有没有需要提前问 HR 的内容。职位名称写得很漂亮，实际工作可能完全是另一回事，至少要把需要确认的问题列出来。

我会把已核验的事实、根据经验作出的推测和暂时查不到的内容分开。这样它可以说话直接，结论也不会装成内幕。

```text
使用 $career-old-hand。请评估我从今天晨报中初筛出的这些岗位，分别说明当前匹配度、成长路线、最大缺口、招聘风险和投递前需要问 HR 的问题。请把已核验事实、合理推测和待确认内容分开，不要因为公司名气大就默认岗位适合我。
```

### 4. 面试指导官

这一段交给 `universal-interview-coach`。

到了笔试面试阶段，网上的题库通常已经够多，难点在于把题目和自己的经历接起来。我会把岗位官网要求、企业公开信息、其他渠道收集到的面试题，以及指定版本的简历交给它。

它要做的是整理一份能拿来突击的资料。哪些问题可能先问，回答可以怎么展开，简历里的哪段经历能作证，项目里哪些细节需要重新回忆，都要写清楚。课程学过的内容、正在补强的内容和已经做过的项目也要分开。面试时可以说自己正在补哪块，不能把计划提前算成经验。

```text
使用 $universal-interview-coach。根据我提供的岗位官网要求、面试题和指定简历，整理一份面试准备资料。请优先列出高频问题、回答结构、我的真实证据和仍需补强的内容，不要把课程学习或计划中的事情写成已经做过。
```

需要 Word 文档时，再补岗位名称和输出格式。资料越具体，准备结果越像一次面试排练，越不像把网上题库重新抄了一遍。

## 总控 skill 会自动拆分四个对话

自己一个个建立任务当然可以，也可以在项目里使用 `campus-job-workflow`，然后说“自动建立四个任务”或“自动拆分四个对话”。

支持创建任务的环境会准备下面四个独立对话。

1. `校招助手`
2. `校招晨报`
3. `校招老油条`
4. `面试指导官`

当前环境不能自动创建任务时，总控 skill 会输出四份可以复制的提示词。它不会假装任务已经建立，侧边栏里没有出现新任务就是没有出现新任务。

四个任务共享项目文件，但不共享聊天历史。晨报可以专心找岗位，风险判断可以专心挑问题，面试指导官也不用在一堆旧消息里重新找我当初为什么想投这个方向。

## 我怎么安排模型

第一次整理资料、建立求职画像、制作简历和理解复杂岗位时，我会优先用 Sol。这个阶段需要它把材料读进去，知道哪些内容可以写，哪些内容要先问我。

后面重复性比较高的岗位检索、信息整理和跟进，可以用 Luna，推理强度设为“极高”。模型选用不用天天重新讨论，复杂的第一次理解用 Sol，后面的重复工作用 Luna，够用就行。

## 安装

把需要的 skill 目录复制到 Codex 的 skills 目录，并保留目录结构。想使用总控 skill 自动拆分任务，就把下面五个目录放在同一层。

- `campus-job-workflow`
- `campus-job-research`
- `career-old-hand`
- `resume-application-tracker`
- `universal-interview-coach`

例如总控 skill 的目录应该是这样。

```text
<CODEX_HOME>/skills/campus-job-workflow/
├── SKILL.md
└── agents/openai.yaml
```

安装后刷新或重启 Codex，让它重新读取 skill 列表。

## 公开仓库里的边界

这里放的是工作方法和 skill 文档，没有个人简历、投递记录、联系方式、账号凭据和本地文件路径。使用时请换成自己的材料，也别把公开仓库里的规则当成某个候选人的固定事实。

模型很勤快，勤快不等于知道我的经历。简历里的事实要来自我提供的材料，岗位信息要尽量回到官方来源核验，没确认的地方就写待核验。

准备材料、填写草稿和整理 Excel 都可以交给它分步处理。最终投递、公开发布、联系招聘方和上传个人文件，需要我在行动前自己确认。

## 用过以后，欢迎告诉我哪里卡住

这套工作流来自真实的投递需求，暂时肯定还有毛边。晨报太吵、岗位核验没跟上、Excel 归档出问题，或者面试资料没有帮上忙，都可以直接写出来。具体的卡点比一句“挺好用的”更容易让我知道下一步改哪里。

提交 Issue 时，写清楚用了哪个 skill、当时想完成什么、实际发生了什么。可以贴脱敏后的最小示例，别把完整简历、联系方式、身份证号、账号信息或公司内部材料直接放到公开 Issue 里。
